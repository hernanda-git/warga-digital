## API Integration

### Endpoints Used

1. **POST `/api/cms/articles/draft`** (Phase 1)
   - Creates draft placeholder
   - Called on first save if articleId is null

2. **PATCH `/api/cms/articles/{id}`** (Phase 1)
   - Updates article with autosave flag
   - Called every 30 seconds on inactivity
   - Called on explicit draft/publish save

3. **GET `/api/cms/articles/{id}`** (existing)
   - Loads article for edit mode
   - Fetches images in article_images array

4. **GET `/api/profile`** (existing)
   - Auth validation in AdminArticlesPage
   - Not called from composer

### Request/Response Examples

**Create Draft:**
```
POST /api/cms/articles/draft
{ temp_title: "My Article" }

Response:
{ article_id: "uuid", is_draft: true, created_at: "..." }
```

**Autosave:**
```
PATCH /api/cms/articles/{id}
{
  title: "Updated Title",
  content: "Updated content",
  autosave: true
}

Response:
{ article: {...}, autosaved: true }
```

**Publish:**
```
PATCH /api/cms/articles/{id}
{
  title: "Final Title",
  status: "published",
  autosave: false
}

Response:
{ article: {...published_at set...} }
```

## User Experience Flow

### Creating a New Article

1. User clicks "Buat Artikel" on list page
2. Navigates to `/admin/articles/compose`
3. Composer page loads (no articleId)
4. User types title → slug auto-generates
5. User types excerpt + content
6. After 30 seconds of inactivity → autosave fires
   - Creates draft via `POST /api/cms/articles/draft`
   - Updates via `PATCH /api/cms/articles/{id}`
   - Shows "Tersimpan X detik lalu"
7. User clicks "Publikasi"
   - Sets status=published
   - Shows "Artikel dipublikasi" toast
   - Redirects to list (in future Phase)

### Editing Existing Article

1. User clicks "Edit" on article card
2. Navigates to `/admin/articles/compose?id={articleId}`
3. Composer loads article data (title, content, etc.)
4. User makes changes
5. After 30 seconds → autosave fires
6. User clicks "Perbarui" to save explicit changes

### Abandoning Draft

1. User opens new article, starts typing
2. Draft created automatically on first autosave
3. User navigates away without publishing
4. `beforeunload` fires with warning: "Anda memiliki perubahan yang belum disimpan"
5. Draft article left orphaned in DB (cleanup in Phase 5)
